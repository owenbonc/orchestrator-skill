# AGENTS.md

Guidance for every agent (and human) working in this repo.

## Source of truth

`SPEC.md` defines what the project does. Read the sections your task touches before writing code. If the spec is wrong or silent on something that matters, raise it. Don't improvise behaviour the spec doesn't describe.

## Conventions

- Write only the current state. No backwards-compatibility shims, versioned comments or dead code. When something changes, change it everywhere and delete the old path.
- Comments say *why* the code can't show, in one line.
- Parse external data with a schema at the boundary, then trust the types inside.
- Domain logic lives in plain, tested modules; apps and UIs are thin adapters.
- Scheduled or retried operations are idempotent.
- Risky logic ships with a behaviour test.
- Done means `scripts/verify.sh` prints READY and the real thing was exercised.
- Priority: quality first. The orchestrated-build skill's default for this project (or tokens first); a request can name the other.
- Stop a server you started by the port it listens on (`lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill`; without `-sTCP:LISTEN`, lsof also lists the port's clients, such as the browser), never by name (`pkill`, `killall`): a name matches the owner's live app too.
- Never commit secrets, local data, or personal content.
- Commits have no co-author or "generated by" lines.

## Skills and where they apply

| Skill | Used for |
|---|---|
| `grilling` (grill-me) | Before each phase or major feature: interview the owner in rounds until the design is settled, then update `SPEC.md`. |
| `ponytail` (full) | All code: the smallest complete change; never cut validation, error handling, security or accessibility. `ponytail-review` in review. |
| pstack (`poteto-mode` and principles) | Engineering principles: model the domain, boundary discipline, type-system discipline, idempotent operations, test behaviour, prove it works. |
| `impeccable` | All UI process: `PRODUCT.md`, `DESIGN.md`, craft floor before edits, `audit` + `critique` after. |
| Emil Kowalski's skills | All UI craft: `emil-design-eng`, `pick-ui-library`, `review-animations`, `animate`, `break-ui`. |
| `thermo-nuclear-code-quality-review` | The review gate for every phase, with a spec-conformance pass against the acceptance criteria. |

Install (Claude Code): the plugins come from the marketplaces `DietrichGebert/ponytail`, `cursor/plugins` (pstack), `pbakaus/impeccable` and `mattpocock/skills`. For Emil's skills, run `npx skills@latest add emilkowalski/skills`. The thermo-nuclear review is the `cursor-team-kit/skills/thermo-nuclear-code-quality-review` folder of `cursor/plugins`, copied to `~/.claude/skills/`.
